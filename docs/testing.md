# Testing Primer

The tests play Primer in a mock of the game (`addon/test/game.lua` over the
kit's `wowmock.lua`, never edited here). The strict game, the secret values, the
harness the matrix is made of and the generator of the API tables are the kit's
too (`../addon-kit/docs/battery.md` is where they are described, and the shape
the other addons follow: Primer's battery was moved there on 5 November 2026). The mock used to accept any call, so a
call the client refuses passed (5 November 2026: `GameTooltip:SetTalent` in
Era's argument order raised "bad argument #3" on Forever). The battery makes
the mock refuse what the client refuses, and plays every class, level and tab.

```bash
bun run battery                          # all of it, in parallel: about 20 seconds (the slowest is Era's matrix)
bun scripts/battery.ts matrix            # the jobs with "matrix" in the name
FOREVER=1 luajit addon/test/matrix.lua   # one job alone, Forever (FOREVER=0 or unset: Classic Era)
FOREVER=1 luajit addon/test/matrix.lua secrets
STRICT=soft luajit addon/test/sim.lua    # list every refusal instead of stopping at the first
STRICT=0 luajit addon/test/sim.lua       # the old, lenient game, to compare
bun run apidocs                          # the generated tables again (the kit's generator), after a pin or a new call
```

`bun run check` runs it (`check:ci` too, which has no family folder: the
generated tables are committed).

## The pieces

| File | What it does |
|---|---|
| `sim.lua` | the rules, the words, the pages, one scenario each (the older test) |
| `strict.lua` (the kit's copy) | wraps the mock's functions and frame methods so a call the documentation refuses raises, naming the function and the argument, and is also kept in `violations` (a `pcall` cannot hide it) |
| `api_<game>.lua`, `evidence_<game>.lua` | generated by the kit's `apidocs.ts` from the pinned Blizzard UI source (`wow-data/ui-pins.json`): the documentation tables, and for a method no table lists, the argument counts Blizzard's own Lua calls it with |
| `strict_test.lua` (the kit's copy), `strict_extra.lua` | the strict game's own test: the kit's cases on widget methods, then Primer's own in `strict_extra.lua`: each bad call listed must be refused (today's `SetTalent` among them) and each good one accepted |
| `sim.lua` (its last scenario) | the Options page (its boxes, `/primer settings`, the minimap right-click, a typo's usage), codes in and out, the line at level 10 and its box, `/primer reset` and `reset yes`, the welcome page (a new character, once, not at the next login or a reload, in a fight, in the family's turn, `welcome` and `export`, no sharing offered, the words per game) |
| `matrix.lua` | every class with content, every level (1, 2, 9, 10, 11, 20, 40, 60), every tab, states: nothing spent, points in each tree, a spec picked, a stored role from before, Hardcore (Era). It opens, draws, hovers (OnEnter, OnLeave) and clicks (OnClick, OnMouseUp) everything shown, then levels up, respecs and fights. After the classes: every class at level 10 under each combination of the Options boxes, and the welcome page (with another character to take, and with its code) walked, hovered and clicked like the window |
| `matrix.lua secrets` | Forever: each call of the game the mock has answers with secret values, whole and field by field, and the page must not raise; the talent calls must leave nothing read. Covered: the mock's `C_*` functions (not `C_Timer`) and `UnitClass`, `UnitName`, `UnitGUID`, `UnitRace`, `UnitSex`, `UnitLevel`, `UnitFactionGroup` (not `GetNumSpecGroups` or other globals) |
| `scripts/battery.ts`, `battery-lib.ts` (the kit's copy) | the jobs, and the kit's runner: all at once, one verdict line each |
| `secrets.lua`, `battery.lua` (the kit's copies) | the secret values and their driver, and the walk, audits, hover and click and verdict the matrix uses |

A case fails on: a Lua error, a fault Primer kept (`ns.faults`), a call the
strict game refused, a frame bigger than the screen or a window anchored off
it, text cut short (`ns.fit`, the mock's `IsTruncated`), a semicolon, an
exclamation mark or a non-ASCII character in a word shown (page, tooltip, chat),
an icon left as the question mark (not in secrets mode, where it is the
fallback), a read of the game in combat.

## Extending it

- A new class: add its content, `bun run guide`. The matrix reads
  `ns.data.classes`, nothing is typed. A new level worth playing: `LEVELS` in `matrix.lua`.
- A new call into Blizzard: `bun run apidocs` (the tables list the namespaces
  and methods Primer's own code names). A function the mock lacks is added to
  `game.lua`, then the strict game checks it the day it is there.
- A method the documentation lacks and Blizzard's source never calls (`GameTooltip:SetTalent` on Forever):
  the strict game refuses it. Prove it in the game, then add `G.strict.ALLOW["Obj:Method"] = "<who saw it, when>"` in `game.lua` after `G.strict.install` with who saw
  it and when. Never to make a run green.
- Text the width estimate calls cut but a person judged fine: `CUT_OK` in `matrix.lua`, with why. Never a reason.

## What it cannot cover

- **The documentation is Blizzard's declaration, not the client.** It lists the longest form of some methods
  (`SetPoint("TOP")` is fine, `SetPoint("LEFT", 4, 0)` is not listed): `OPTIONAL_FROM` and `EXTRA_SIGNATURES` in
  the kit's `strict.lua` are the places it is loosened, each a thinner spot in the net. A string enum's values
  (`FramePoint`, `DrawLayer`...) are checked as strings only. Types the documentation does not define are
  counted as unchecked and printed at the end of a sim.
- **The source is a few builds behind the client** (`wow-data/docs/ui-source.md`), and says what Blizzard's files
  declare. A method Blizzard's Lua never calls may still exist; a call it makes may still fail.
- **Methods are matched by name, not by widget.** `frame:SetText()` on a plain Frame passes if any widget
  documents `SetText`; the client would raise. `evidence` pools every object the same way. Enum arguments accept
  numbers or strings, function arguments accept tables.
- **Globals the documentation lacks** (`CreateFrame`, `InCombatLockdown`, `GetNumTalents`, `PlaySound`...) are not
  checked and not in the unchecked list.
- **Widget scripts and templates** (`SetScript` events, `UIPanelButtonTemplate`, `PanelTemplates_*`) are not
  checked against anything.
- **No layout.** The mock does not place frames: size against the screen and the window's anchor are checked,
  overlaps, clipping, the look and the fonts are not. Text width is an estimate (0.55 of the size a character).
- **Secret values** are emulated (a userdata that keeps its type and raises on indexing, `#`, `pairs`, `ipairs`, arithmetic, concatenation and ordering; `==` against it and using it as a table key do not raise). The documentation flags no
  return of Primer's `C_Traits` calls (only `SecretArguments`) and the unit calls as restricted for other
  units; the run goes further than the flags on purpose. How the client really hides a value is for the game to say.
- **Events and timing** are the mock's (`PLAYER_LEVEL_UP`, a respec, a fight are fired by hand).
- **Taint**: nothing here sees it.

## What a person must look at in the game (the checklist)

1. Open `/primer` on each tab at level 1, 10 and 40: nothing overlaps, nothing runs off the window.
2. Hover a talent in the Talents tab and a row on the Level tab: a tooltip with the spell, no error (Forever and Era).
3. Level 10 with a point unspent (Forever): the spec question, a button each, "Not yet" works.
4. Pick a spec, reload: the same spec and role come back.
5. Respec: the page follows within a second, no red error box.
6. Fight and leave it: the window reads nothing while fighting and catches up after.
7. If a page ever says "The guide cannot read your character" (`/primer debug` says why): its heading fits.
8. Every reason is printed in full, wrapped, none ends in "...".
9. Icons: every spell and talent has its own picture, no question marks.
10. The minimap button, the logo and the portrait look right, and Keyring's button opens the window.
11. Hardcore realm (Era): the Class tab shows the Hardcore lines.
12. A character of a class with no guide: the class page, no build marked as yours.
13. The Options page (Esc, Options, AddOns, Primer, or `/primer settings`, or a right-click on the minimap button): two boxes and "Copy settings from", each box does what it says, no error.
14. A new character: the welcome page a few seconds after the login, the words fit, the minimap box and the chat box act, "Open the book" opens the window, it does not come back at the next login. `/primer welcome` shows it again.
15. `/primer reset`, then `/primer reset yes`: the level-10 question comes back.
